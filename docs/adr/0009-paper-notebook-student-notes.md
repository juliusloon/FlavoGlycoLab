# ADR 0009：论文笔记本与学生阅读笔记

- 状态：accepted
- 日期：2026-10-25
- 决策来源：human_direct（展示需求）；记录结构与技术手段由agent选择，不代表教师审定。
- 负责人：项目所有者；技术执行：Cano。
- 关联TASK：TASK-047；TASK-050按用户新指令复审阅读器与展示。

## 背景
用户要求把论文详细对照从导入页移到任务01，并通过四便签浮窗随时阅读三篇原文和写笔记。既有学生记录以run为唯一实验草稿，按当前站点localStorage保存，支持快照和导出；来源、原文与科学准入各自已有唯一登记。

## 决定
1. paper-notebook.js/css只负责原生dialog、四个便签及同源PDF读取；引用demo-content的既有解读与caseComparison，不另存科学摘要或来源登记。前端显示不改变PDF授权状态。
2. run.paperNotes以三个既有source_id为键，每篇最多8000字符；仅学生自述。缺字段的旧记录补空对象，非法来源/类型/超长内容拒绝载入。复用当前实验的保存、历史快照和JSON/Markdown导出，不建立第二个笔记存储。
3. 阅读和笔记不修改学习答案、任务通过、AI使用事实、上下文修订、样品观测或评分。更换路线保留阅读笔记，新实验清空，历史快照独立保全。
4. 导入前两幕保持顺序判断；进入第三幕即可开始主线，不再用论文打开次数证明学习完成。原papers字段只兼容历史，不作为当前门槛。

5. TASK-050改用固定本地PDF.js 5.4.624在paper-pdf-reader.js中读取同源原PDF，逐页canvas与可选择文本层展示，白底/内边距由本项目控制，不加载浏览器PDF工具栏/目录。主库/worker保留原始发布字节，仅扩展名从.mjs改.js适配已有静态服务；LICENSE与provenance登记版本、来源、包完整性及文件SHA。不增加后端配置或运行CDN；不重新生成/改写来源PDF。
6. 笔记本不显示标题副句、PDF标签与常驻保存/权利说明；图标便签保留完整可访问名称，窗口独立关闭按钮/Esc回焦。许可/审定登记和真实错误恢复仍在各自职责内维护。

## 备选方案
- 独立localStorage笔记键：会使新实验、快照和导出产生两份生命周期，因此复用run。
- 每张解读卡独立内嵌PDF：无法实现随主线调用的四便签阅读窗口；任务01改为统一入口，其他已有阅读能力保留。

## 影响与风险
笔记仅保存在当前浏览器和站点，换设备/站点源不会同步；保存失败必须明示并允许导出。PDF内嵌阅读由本地渲染器负责，逐页懒渲染且在尺寸变化/取消/新实验时回收资源，加载异常按需提供原PDF新标签页与重试。三状态门及出版方rights_verified=false均不变。

## 复审条件
引入账号/跨设备同步、更新PDF.js或更换渲染器、修改笔记的证据用途或变更教学准入时复审，不以工程通过替代教师/发布批准。
