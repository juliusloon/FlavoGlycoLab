# ADR 0008：独立页面地址与共享界面组件

- 状态：accepted
- 日期：2026-10-24
- 决策来源：human_direct（页面拆分与规范化）；技术方案由Cano按授权选择，不表示教师审定。
- 负责人：项目所有者；执行者Cano
- 关联TASK：[TASK-037](../tasks/TASK-037-page-system-components.md)

## 背景
原学生端使用少量hash入口，大部分幕/任务/阶段仅存在于运行内存。案例页、数据页各自维护页头和视觉变量，开发容易产生差异。所有者要求拆成便于回退和重新进入的子页面，并提供统一规范与组件库，明确不加面包屑栏。

## 决定
- 保留原生HTML/CSS/ES模块和现有静态服务器。学习页使用 `#/home`、`#/intro/N`、`#/stage/N`、`#/task/NN`、`#/papers?stage=N`、`#/records`；案例、数据和组件展示继续为独立HTML入口。
- `navigation.js` 唯一负责解析、访问和续接。地址是视图，实验答案/阶段约束仍归lab-state、learning-state、quest-state；访问不得绕过原规则。last-page仅为界面偏好，恢复时重新检查访问条件。
- `design-tokens.css` 是唯一视觉变量源，`components.js` / `components.css` 是站点导航与通用控件的唯一维护位置；领域视图复用它们。`components.html` 使用生产组件，`docs/design/interface-system.md` 唯一维护调用和页面规范。
- 统一站点导航与返回/续接入口，不使用面包屑。保留原任务内论文对话框，与独立论文页共用同一渲染函数，通过standalone选项区分对话框外壳。

## 备选方案
- 单一工作台继续保存内存视图：无法满足可复制地址、刷新与浏览器历史要求。
- 每个任务复制一份HTML和状态逻辑：重复24份内容、控件与门禁，易形成多份真值。
- 改为框架与服务端路径路由：当前无须增加构建/运行依赖及静态服务回退配置；本任务沿用现有栈完成需求。

## 影响与风险
hash深链直接适用于现有静态服务；旧学习状态无需新增业务字段。任务地址可能因上游改动失效，必须显示恢复入口；localStorage仍按浏览器/源隔离。页面数量增加不改变候选数据、教师审定、真实观测或公众教学发布状态。共享组件变化须同时验收实验/案例/数据/组件页。

## 复审条件
如引入正式师生账户、跨设备持久化、服务端授权、SSR或正式平台路由，重新审查地址与恢复协议；不得把当前客户端门禁当作服务器安全权限控制。变更另立批准TASK并保留旧地址迁移。
