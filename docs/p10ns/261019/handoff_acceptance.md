## 每份交付的统一接收方式

1. 成员从最新main创建自己的短期codex/分支，修改本人交付文件后提PR；已经在其它分支制作的内容给出实际分支/提交/文件定位，不重复录入同一真值。普通开发不需research包；处理原始历史证据时按协作说明使用内部离线包。
2. 交接必须提供：交付ID、负责人、文件/分支或PR、版本、提交时间、完成范围、未解决项、来源定位、许可/教师状态。没有PR时可先交文件，但记录实际存放位置和SHA，不能只口头说“完成”。
3. 接收状态为“未登记接收→已收到待检查→需补充/工程检查通过→已接入”。工程检查通过不等于教师批准。科学/许可判断缺失时可保留候选，但不进入审定观测/正式评分。
4. LJX按下面的字段合同检查、列缺项、指定反馈责任人与下一时点。准备稿可接收但不得勾正式版本完成。不同版本不覆盖原件，更新版本号/变更说明并保留前版或Git提交。
5. 不把受限原件、全文以外的未授权载荷、private、密钥、研究包或大视频放进公共Git；原创Markdown和许可明确的元数据可走PR。三篇已有PDF以metadata/public_sources.json的原路径/SHA引用，避免要求重复上传。录像按内部交接方式提供路径与SHA。

## A. 文献摘录接收合同（HYK）

交付文件建议为本目录literature_extraction_table.md；正文可引用附带的逐记录CSV，引用其相对路径/SHA。v1要求三篇均有书目、现有全文获取状态、已知字段与缺项；v2补全字段，不用“待补”掩盖原文未报告。

| 必查项 | 具体检查 | 进入哪里 |
| --- | --- | --- |
| 身份与原件 | source_id、DOI、原PDF路径/SHA、摘录人/日期；核对现有三个PDF，不因文件名不同重复索取 | source_registry/public_sources继续唯一登记，摘录表只引用 |
| 实验体系 | R1/R2/R3分别列体系、酶/宿主/来源、底物/供体、辅助蛋白和改造点；跨体系数据不合并 | 给ZYT案例核对与LYW条件设计，不直接改前端原型 |
| 条件与测量 | 每个值带单位、基准、原文页/表/图定位；浓度/pH/温度/体积/酶量/时点/对照/重复/方法逐项标状态 | 后续受控数据候选，只在许可与教师准入后接D1 |
| 结果语义 | 0只用于真实明确零观测；缺失/未报告/未摘录/待授权分开，未知数值null；记录标准曲线、稀释/衡算等支持信息 | 缺口清单与待审表，不自动显示产率 |
| 支持范围 | 哪些条件真实测过、哪些不可外推、数据能否再分发、正文/SI定位是否充分 | T-H2与后续D1合同；没范围则继续拒绝数值 |

检查数值逐项可回到原文定位；核验到原件SHA不同即停接该来源，保留双方文件/登记并追查，不改指纹绕过。

## B. 案例证据接收合同（ZYT）

交付case_evidence_table.md，可附CSV；人审状态继续candidate/pending_teacher_review。5类身份材料、21条历史命中、R1/R2反应卡三块分别列。

- 身份卡：名称/结构标识/分子式/分子量/糖连接及第二来源定位。无法唯一给出标识或数值的条目明确原因，转专业审核，不能为凑表硬填。
- 21条命中：record_id/source_id/原路径及SHA/定位/方向/是否酶促/主案例关系/重复判断/状态齐全；历史产物命中不等于酶促实验。与现有22条准入登记（1主案例＋21命中）对齐，不凭新表替换旧登记。
- 反应卡：酶身份/来源、底物、供体、辅助体系、方向、已知条件及限制均有来源；未知保留缺失。至少10处路线字段比对作为原W-02工程验收依据。
- 接入映射：非数值候选表述经范围核对后进入frontend/student/content/demo-content.json；身份图示与结构面板先列实施需求。原案例准入表和审定状态仍由data/registries/case_admission.csv负责，不把前端JSON当第二套准入真值。
